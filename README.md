# СтатМетод — конструктор и электронный реестр ОСМ

Учебный проект на **FastAPI + SQLite + React + TypeScript + Ant Design**.

Это **доработанная версия предоставленного проекта «Конструктор официальной статистической методологии»**, дополненная электронным реестром из учебного архива «Реестр ОСМ». Старый конструктор сохранён, а реестр доступен отдельной вкладкой в верхней части приложения. 
## Быстрый запуск

**Нужно:** Python 3.10+ и Node.js, совместимый с Vite 8 (Node.js 20.19+ или 22.12+). Для установки пакетов нужен интернет. SQLite ставить отдельно не нужно.

### 1. Backend

Откройте терминал в папке проекта:

```bash
cd backend
python -m venv .venv
```

Активируйте виртуальное окружение:

- **Windows (PowerShell):** `.venv\Scripts\Activate.ps1`
- **Windows (cmd):** `.venv\Scripts\activate.bat`
- **Linux/macOS:** `source .venv/bin/activate`

Затем установите зависимости и запустите сервер:

```bash
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Backend: http://127.0.0.1:8000/docs — Swagger с API конструктора и реестра.

Для нового реестра ключи YandexGPT не требуются. Для сохранения старого ИИ-помощника по желанию создайте `backend/.env` по примеру `backend/.env.example` и добавьте собственные ключи. **Не публикуйте файл `.env`**.

### 2. Frontend

Во **втором терминале** из корня проекта:

```bash
cd frontend
npm ci
npm run dev
```

Откройте **http://localhost:5173**. В верхнем меню находятся две вкладки: **«Реестр ОСМ»** и **«Конструктор методологии»**.

> Не переносите папки `node_modules` и виртуальное окружение со старого компьютера. `npm ci` и `pip install` создают зависимости, соответствующие текущей платформе.

## Что умеет реестр

1. Показывает все исходные 447 ОСМ с пагинацией; записи без документов также видны.
2. Ищет по наименованию, номеру и названию приказа, а также идентификатору ОСМ (без учёта регистра кириллицы).
3. Фильтрует по признаку соответствия приказу №548, наличию файла, органу, позиции ФПСР и диапазону дат приказа.
4. Открывает карточку с реквизитами приказа, позициями ФПСР, справочной ссылкой и документами.
5. Позволяет смотреть PDF в окне, читать *текстовые абзацы* DOCX (без сохранения таблиц и форматирования) и скачивать оригиналы.
6. Добавляет ОСМ с реквизитами и PDF/DOCX через форму **«Добавить ОСМ»**. Допускается ОСМ без документа.
7. Принимает до **10 файлов на одну ОСМ**, не более **25 МБ каждый**, проверяет тип содержимого и вычисляет SHA-256. Идентичные файлы хранятся в одном экземпляре.
8. Сохраняет новые данные **в SQLite на backend**, после перезапуска они остаются в реестре.
9. Выгружает текущую выборку в CSV (UTF-8 с BOM, разделитель `;`).

## Модель данных

Файл `backend/data/osm_registry.sqlite` — исходная локальная учебная база, поставляемая в архиве.

| Таблица | Содержимое | Ключ |
| --- | --- | --- |
| `osm` | ОСМ и все исходные реквизиты | `osm_id` |
| `documents` | Уникальные файлы и относительные пути | `sha256` |
| `osm_documents` | Связи между ОСМ и файлами | `(osm_id, document_sha256)` |
| `meta` | Сведения о происхождении выгрузки | `name` |

Оригиналы находятся в `backend/data/Документы_ОСМ/`. На одну ОСМ может приходиться несколько файлов, а на один файл — несколько ОСМ. Хранение файла не дублируется по количеству ОСМ. Новые записи получают ID вида `OSM-USER-...`.

### Состав исходного набора

| Контрольное значение до добавления пользовательских ОСМ | Количество |
| --- | ---: |
| ОСМ | 447 |
| Признак №548 = «Да» / «Нет» | 201 / 246 |
| ОСМ с файлами / без файлов | 209 / 238 |
| Оригинальные файлы PDF / DOCX | 24 / 44 |
| Уникальные документы | 68 |
| Приказы | 160 |
| Исходные строки таблицы связей | 481 |
| Непустые связи ОСМ — документ | 243 |

**Важная оговорка из архива:** связь исходного документа с ОСМ установлена **по приказу** и **не подтверждает принадлежность содержания файла конкретной ОСМ**. Пометка №548 отражает только исходную классификацию. Данные — снимок от **20.10.2026**, не автоматически обновляемый реестр действующих нормативных актов.

Из `sources/` можно просмотреть `MANIFEST.json`, описание полей и техническое задание, а также оригинальные четыре CSV. Физические документы не менялись при переносе в проект.

## API

| Метод | URL | Назначение |
| --- | --- | --- |
| GET | `/api/registry/stats` | Счётчики и список органов |
| GET | `/api/registry/methodologies` | Фильтры, поиск, `page`, `page_size` |
| GET | `/api/registry/methodologies/{osm_id}` | Детальная карточка и связанные документы |
| POST | `/api/registry/methodologies` | Создать ОСМ через `multipart/form-data` (поля + `files`) |
| GET | `/api/registry/documents/{sha256}/file` | Открыть PDF / скачать оригинал (`?download=true`) |
| GET | `/api/registry/documents/{sha256}/preview` | Текстовый предпросмотр DOCX |
| GET | `/api/registry/export.csv` | CSV текущей выборки |
| GET | `/api/template` | Сохранённый API конструктора |
| POST | `/api/export/docx` | Сохранённый экспорт Word |

Список поддерживает параметры `q`, `complies_548=yes|no`, `has_documents=yes|no`, `authority`, `date_from`, `date_to`, `fpsr`.

## Проверка

```bash
cd backend
python -m unittest discover -s tests -v
```

Пять тестов выполняются на **временной копии базы** и не изменяют приложенный набор. Они проверяют контрольные количества, фильтры, карточку, доступ к документу, CSV, сохранение новой ОСМ и двух вложений, повторную загрузку одного файла и откат при недопустимом файле.

Для фронтенда:

```bash
cd frontend
npm ci
npm run build
```

## Ограничения и безопасность

Это **учебный локальный прототип**, а не система для открытой сети или эксплуатации с несколькими пользователями. В реестре пока **нет авторизации, прав доступа, журнала изменений, антивирусной проверки загрузок, резервного копирования, утверждения изменений и миграций схемы**. Не публикуйте такой сервер в интернете. Рекомендованный запуск — `127.0.0.1`, файлы документов доступны пользователям локального API. Перед передачей оригинальных документов третьим лицам проверьте права на их распространение.

Для учебной демонстрации достаточно двух запущенных терминалов. **Чтобы сохранить добавленные методологии**, не удаляйте `backend/data/osm_registry.sqlite` и папку `backend/data/Документы_ОСМ/`; регулярно делайте резервную копию обоих объектов при выключенном backend.
