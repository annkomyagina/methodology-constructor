# JSON-шаблоны и справочник ФПСР

Документ описывает, как устроены исходные JSON-материалы и как их
использует приложение. Проект не копирует структуру JSON буквально —
он интерпретирует её и превращает в интерфейс конструктора и в
Word-документ.

## 1. Состав исходных материалов

В папке `backend/data/` находятся:

- `template_manifest.json` — манифест: общее описание шаблона и список
  7 разделов;
- `sections/section_01_general.json` … `section_07_dissemination.json` —
  описания разделов;
- `fpsr_catalog.json` — справочник Федерального плана статистических
  работ (1 939 позиций).

Все файлы в UTF-8. Пути не зашиты в код: `template_loader.py` читает
их относительно расположения модуля.

## 2. Манифест

Файл `template_manifest.json` содержит:

- `template_id`, `version`, `description`;
- `rules` — общие правила (например, что фиксированный текст должен
  совпадать в UI и Word);
- `global_settings` — шрифт Word, размер, текст заглушки для
  незаполненного обязательного поля;
- `sections[]` — массив из 7 объектов с полями `id`, `number`, `title`,
  `file`, `required`.

Манифест — единый источник списка разделов. Frontend читает его через
`GET /api/template` и строит левое меню. Backend использует его при
генерации Word, чтобы обойти все разделы в правильном порядке.

## 3. Раздел

Каждый JSON-раздел содержит:

    {
      "section_id": "section_01_general",
      "number": "I",
      "title": "I. Общие положения",
      "description": "...",
      "required": true,
      "fields": { ... },
      "validation": { ... },
      "document_opening": { ... },
      "blocks": [ ... ]
    }

### 3.1. fields

Словарь: имя поля → его описание. Пример:

    "methodology_name": {
      "label": "Название Методологии",
      "type": "inline",
      "placeholder": "название Методологии",
      "required": true,
      "linked": true,
      "hint": "Укажите полное название...",
      "source_comment": "...",
      "ui_notes": "..."
    }

Поле `type` определяет, какой UI-компонент и какой рендерер Word
использовать. Поддерживаются типы:

- `inline` — однострочное поле;
- `block` — многострочное;
- `choice_text` — встроенный выбор из короткого списка;
- `editable_ending` — свободный текст, часто используется для
  продолжения фразы;
- `repeated_group` — повторяемые строки;
- `fpsr_positions` — специальное поле для справочника ФПСР;
- `formula_repeated_group` — расчётные блоки;
- `classifier_paragraphs` — выбор из 19 классификаторов.

### 3.2. validation

Определяет правила обязательности:

    "validation": {
      "required": true,
      "required_items": [
        "methodology_name",
        "rosstat_legal_subpoint",
        "information_characteristic",
        "information_usage_purpose",
        "fpsr_positions"
      ],
      "optional_items": ["additional_legal_basis_ending"]
    }

Элемент `required_items` может быть:

- строкой — именем поля;
- объектом с `type` и `id` для повторяемых групп и расчётных блоков.

Frontend читает `validation` и подсвечивает незаполненные пункты в
сайдбаре. Пользователь видит статус раздела: пусто, в работе,
проблемы, заполнено.

### 3.3. blocks

Список блоков, которые нужно отрисовать в разделе. Это основной
элемент интерпретации. Каждый блок имеет поле `type`:

- `heading` — заголовок раздела;
- `paragraph` — абзац, состоящий из частей;
- `field_block` — отдельное поле как самостоятельный блок;
- `repeatable_group` — таблица повторяемых строк;
- `formula_repeated_group` — расчётные блоки;
- `classifier_paragraphs` — выбранные классификаторы;
- `optional_group` — включаемые блоки (ЕМИСС, сайт Росстата, доп.);
- `empty_state_output` — заглушка на случай, если ничего не выбрано
  (используется только при генерации Word).

### 3.4. paragraph и его части

Абзац состоит из массива `parts`. Каждая часть:

- `{"type": "text", "text": "..."}` — фиксированный текст;
- `{"type": "field", "field": "methodology_name"}` — подстановка поля;
- `{"type": "choice_text", "field": "...", "options": [...]}` — встроенный
  выбор;
- `{"type": "fpsr_reference", "field": "fpsr_positions", "mode": "editable"}`
  — вставка позиций ФПСР.

Один и тот же абзац рендерится и в интерфейсе, и в Word. Для этого
backend использует ту же логику разбора `parts`.

## 4. Справочник ФПСР

Файл `fpsr_catalog.json`:

    {
      "version": "1.0",
      "items_count": 1939,
      "items": [
        { "number": "1.1.1.", "title": "..." },
        ...
      ]
    }

Особенности использования:

- справочник загружается один раз за сессию и кэшируется в памяти
  фронтенда;
- поиск идёт по номеру и названию (одновременно);
- выбранные позиции хранятся как массив объектов
  `{ "position": "1.2.2.", "title": "..." }`;
- в пункте 1.3 позиции выводятся в творительном падеже
  («позицией 1.2.2.» или «позициями 1.2.2., 1.2.6.»);
- в пункте 7.2 те же позиции подставляются в дательном падеже
  («согласно позиции 1.2.2. ФПСР»).

Грамматика собирается утилитой: одна позиция — единственное число,
несколько — множественное. Никакой ручной работы пользователю не
требуется.

## 5. Связи между разделами

Два типа связей:

1. **Linked-поля.** Например, `methodology_name` заполняется один раз,
   но используется и в шапке документа, и в пункте 1.1. Значение
   хранится в общем store, оба места подставляют его.

2. **Ссылки на поле по имени.** Например, `fpsr_positions` заполняется
   в разделе I, а в разделе VII читается в режиме `mode: "readonly"`.
   В интерфейсе — то же значение, но в другом падеже.

Дополнительно, расчётные блоки в разделе VI автоматически создаются
по списку показателей из раздела IV. Если пользователь добавил новый
показатель — новый расчётный блок появляется в VI. Если удалил —
исчезает. Это описано в JSON через `source: "indicators"`.

## 6. Почему JSON не копируется в код

Данные шаблона — это предметная область, а не код. Их можно менять без
пересборки проекта:

- чтобы добавить новый раздел, достаточно положить JSON в
  `backend/data/sections/` и добавить ссылку в манифест;
- чтобы поправить подсказку, поменять одну строку в JSON;
- чтобы изменить правило обязательности — то же самое.

Такой подход позволяет отделить разработку приложения от работы
методологов: методологи правят шаблон, разработчики — код.

## 7. Как шаблон влияет на Word

Word-документ собирается **на основе того же JSON**:

- фиксированный текст берётся из `parts` с `type: "text"`;
- значения — из `values` пользователя по имени поля;
- повторяемые группы рендерятся циклом, с учётом `punctuation`;
- обязательные незаполненные поля подставляются как
  `"________________"` (из `global_settings.empty_required_field_output`);
- подсказки и `ui_notes` **не** попадают в Word — это UI-информация.
