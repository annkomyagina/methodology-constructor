# Интеграция с YandexGPT

В приложении встроен ИИ-помощник на базе YandexGPT. Он помогает
методологу формулировать положения, проверять текст и разбираться в
требованиях к разделам. Все обращения к модели идут через backend —
API-ключ никогда не попадает в браузер пользователя.

## 1. Зачем нужен ИИ в конструкторе

Подготовка официальной статистической методологии — это текстовая
работа с жёсткими требованиями к стилю и структуре. ИИ помогает на
нескольких этапах:

- объяснить, что требуется в конкретном разделе;
- улучшить формулировку, сделав её более официальной;
- предложить варианты текста для поля;
- проверить раздел на противоречия и неполноту.

ИИ не заполняет документ сам и не принимает решений за пользователя.
Все предложения — только варианты, которые человек либо применяет,
либо отклоняет.

## 2. Схема работы

    Пользователь   →   Frontend   →   Backend   →   YandexGPT
         ↑                                            │
         └─────────────── ответ ──────────────────────┘

Подробнее:

1. Пользователь выбирает раздел и нажимает одну из кнопок в панели
   «ИИ-помощник»: «Объяснить», «Улучшить», «Предложить», «Проверить».
2. Frontend собирает контекст: название раздела, описание, при
   необходимости текст пользователя и значения других полей проекта.
3. Frontend отправляет POST-запрос на `/api/ai/assist`.
4. Backend формирует промпт с системной инструкцией и контекстом,
   обращается к YandexGPT через HTTPS.
5. Ответ возвращается во фронтенд и отображается в панели помощника.
6. Пользователь сам решает, что делать с полученным текстом.

## 3. Backend: эндпоинт `/api/ai/assist`

Принимает JSON:

    {
      "action": "improve" | "explain" | "suggest" | "check",
      "section_title": "I. Общие положения",
      "section_description": "...",
      "field_label": "...",
      "field_hint": "...",
      "current_text": "...",
      "context": { "methodology_name": "...", ... }
    }

Возвращает:

    { "answer": "текст ответа модели" }

Внутри используется системный промпт, который:

- задаёт роль («помощник методолога Росстата»);
- требует отвечать на русском языке в официальном стиле;
- запрещает выдумывать нормативные акты и ссылки;
- ограничивает длину ответа.

Для каждого действия (`action`) есть отдельная инструкция:

- **improve** — улучшить формулировку, сохранив смысл;
- **explain** — объяснить, что требуется в разделе;
- **suggest** — предложить 1–2 варианта текста;
- **check** — перечислить замечания списком.

## 4. Обращение к Yandex Cloud

Используется REST-эндпоинт Foundation Models:

    POST https://llm.api.cloud.yandex.net/foundationModels/v1/completion

Заголовки:

    Authorization: Api-Key <API_KEY>
    x-folder-id: <FOLDER_ID>
    Content-Type: application/json

Тело запроса:

    {
      "modelUri": "gpt://<FOLDER_ID>/yandexgpt-lite/latest",
      "completionOptions": {
        "stream": false,
        "temperature": 0.3,
        "maxTokens": 600
      },
      "messages": [
        { "role": "system", "text": "..." },
        { "role": "user",   "text": "..." }
      ]
    }

Выбрана модель `yandexgpt-lite`:

- дешёвая в базовом варианте;
- достаточная для коротких задач (3–8 предложений);
- быстрый отклик (2–8 секунд).

При необходимости модель меняется одной строкой на `yandexgpt/latest`.

## 5. Хранение ключей

Ключи хранятся в файле `backend/.env`:

    YANDEX_FOLDER_ID=ваш_folder_id
    YANDEX_API_KEY=ваш_api_key

Файл читается модулем `python-dotenv` при старте backend.
Переменные **не попадают** в код и **не отправляются** во frontend.

Если переменные не заданы, эндпоинт `/api/ai/assist` возвращает ошибку
с понятным текстом, но остальные функции приложения продолжают работать.

## 6. Как получить ключи

1. Зарегистрироваться в Yandex Cloud.
2. Создать каталог (folder) — это будет `FOLDER_ID`.
3. Создать сервисный аккаунт с ролью `ai.languageModels.user`.
4. Выпустить API-ключ для сервисного аккаунта.
5. Скопировать секрет в `backend/.env`.

Проверить доступ можно тестовым запросом из терминала — ожидаемый
ответ — JSON с текстом модели.

## 7. Ограничения

- Модель не получает весь документ целиком — только релевантный
  контекст (не более 6 строк из заполненных полей и текущий текст).
  Это снижает риск утечки и уменьшает стоимость запроса.
- ИИ не пишет в документ автоматически: ответ возвращается как
  предложение, применять его или нет — решает пользователь.
- Модель не заменяет собой нормативную базу: она не даёт ссылок на
  законы и постановления, которых не было в промпте.

## 8. Возможные расширения

Архитектура позволяет добавить:

- **интеллектуальный импорт**: пользователь загружает существующий
  DOCX или TXT, а модель размечает его по полям шаблона;
- **автоматическую проверку связности** всего документа;
- **предложения по формулам** на основе выбранных показателей;
- **краткое резюме** заполненного проекта для быстрой проверки.
