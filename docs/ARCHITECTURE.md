# Архитектура проекта

Документ описывает устройство прототипа конструктора официальной
статистической методологии: из каких компонентов состоит система, как
они взаимодействуют и почему выбраны те или иные технические решения.

## 1. Общая схема

Система состоит из двух независимых приложений — backend и frontend —
которые общаются по HTTP через REST API.

    ┌───────────────────────────┐
    │        Браузер            │
    │  ┌─────────────────────┐  │
    │  │  Frontend (React)   │  │
    │  │  localhost:5173     │  │
    │  └──────────┬──────────┘  │
    └─────────────│─────────────┘
                  │ HTTP /api/*
                  ▼
    ┌───────────────────────────┐
    │      Backend (FastAPI)    │
    │      localhost:8000       │
    │  ┌─────────────────────┐  │
    │  │   JSON-шаблоны      │  │
    │  │   Справочник ФПСР   │  │
    │  │   Генератор DOCX    │  │
    │  │   YandexGPT         │  │
    │  └─────────────────────┘  │
    └─────────────│─────────────┘
                  │ HTTPS
                  ▼
    ┌───────────────────────────┐
    │       Yandex Cloud        │
    │    Foundation Models      │
    └───────────────────────────┘

Такое разделение даёт три преимущества:

- API-ключ YandexGPT хранится только на сервере и никогда не попадает
  в браузер пользователя;
- шаблоны методологии читаются из единого источника — и frontend, и
  backend используют одни и те же JSON-файлы;
- frontend и backend можно развивать и заменять независимо друг от друга.

## 2. Технологический стек

| Слой       | Технология                       | Назначение                             |
|------------|----------------------------------|----------------------------------------|
| Frontend   | React + TypeScript + Vite        | интерфейс конструктора                 |
| UI         | Ant Design                       | готовые поля, формы, модальные окна    |
| Состояние  | Zustand + persist                | хранение данных проекта                |
| Формулы    | KaTeX                            | предпросмотр формул                    |
| Backend    | Python 3.10 + FastAPI            | REST API                               |
| Word       | python-docx                      | генерация DOCX                         |
| ИИ         | YandexGPT (Foundation Models)    | интеллектуальный помощник              |
| Хранение   | localStorage (браузер)           | сохранение проекта между сессиями      |

Выбор обоснован так:

- **FastAPI** — минимальный boilerplate, автоматическая документация
  (Swagger), удобная работа с JSON и телом запроса;
- **React** — компонентный подход хорошо ложится на структуру шаблона:
  каждый тип блока — отдельный компонент;
- **Ant Design** — не нужно изобретать формы, поля, модалки, теги;
- **Zustand** — состояние проекта с автоматическим сохранением в
  localStorage без Redux-обвязки;
- **python-docx** — программная сборка документа гибче, чем docxtpl:
  структура документа заранее неизвестна и зависит от данных;
- **YandexGPT** — рекомендован в проектном задании и удобен для
  русскоязычных официальных текстов.

## 3. Backend

Все файлы backend находятся в `backend/app/`.

    backend/
    ├── app/
    │   ├── __init__.py
    │   ├── main.py              # FastAPI-приложение и эндпоинты
    │   ├── template_loader.py   # чтение JSON-шаблонов
    │   └── word_builder.py      # генерация DOCX
    ├── data/
    │   ├── template_manifest.json
    │   ├── fpsr_catalog.json
    │   └── sections/            # 7 JSON-файлов разделов
    └── requirements.txt

### 3.1. main.py

Точка входа приложения. Содержит:

- настройку CORS (разрешает запросы с `localhost:5173`);
- эндпоинты;
- интеграцию с YandexGPT.

Список эндпоинтов:

| Метод | URL                             | Назначение                        |
|-------|---------------------------------|-----------------------------------|
| GET   | /api/health                     | проверка доступности              |
| GET   | /api/template                   | манифест шаблона                  |
| GET   | /api/template/sections/{id}     | JSON одного раздела               |
| GET   | /api/fpsr                       | справочник ФПСР                   |
| POST  | /api/export/docx                | генерация Word                    |
| POST  | /api/ai/assist                  | обращение к YandexGPT             |

### 3.2. template_loader.py

Отвечает за чтение JSON-файлов:

- `load_manifest()` — читает `template_manifest.json`;
- `load_section(section_id)` — по id раздела находит его файл в манифесте
  и читает содержимое;
- `load_fpsr()` — читает справочник.

Все файлы читаются в UTF-8. Путь к папке `data` вычисляется относительно
расположения модуля, поэтому backend можно запускать из любого каталога.

### 3.3. word_builder.py

Содержит функцию `build_document(values)`, которая принимает словарь
значений проекта и возвращает байтовый поток с готовым DOCX.

Логика рендера:

1. Создаётся документ `python-docx`.
2. Устанавливается базовый стиль: Times New Roman 14.
3. Рендерится титульный блок (УТВЕРЖДЕНА / приказом Росстата / дата).
4. Рендерится главный заголовок методологии.
5. Для каждого из 7 разделов вызывается `_render_section`, который идёт
   по блокам и вызывает нужный рендерер.

Поддерживаются все типы блоков шаблона:

- `heading` — заголовок;
- `paragraph` — абзац из частей (текст + поля);
- `field_block` — отдельное поле-блок;
- `repeatable_group` — повторяемые строки (с пунктуацией `;` и `.`);
- `classifier_paragraphs` — выбранные классификаторы;
- `optional_group` — включаемые блоки (ЕМИСС, Росстат, доп.);
- `formula_repeated_group` — расчётные блоки с формулами.

Формулы разбираются функцией `_add_formula_runs`:

- латинские буквы — курсив;
- `_индекс` — подстрочный индекс;
- `^степень` — надстрочный индекс;
- остальное — обычный текст.

Это даёт в Word визуально корректные формулы без использования картинок.

## 4. Frontend

Все файлы frontend находятся в `frontend/src/`.

    frontend/src/
    ├── api/
    │   └── client.ts               # запросы к backend
    ├── components/
    │   ├── AiAssistant.tsx
    │   ├── BlockRenderer.tsx       # главный диспетчер блоков
    │   ├── ClassifierParagraphs.tsx
    │   ├── FormulaBlock.tsx
    │   ├── OptionalGroup.tsx
    │   ├── ParagraphBlock.tsx
    │   ├── RepeatableGroup.tsx
    │   └── fields/
    │       ├── BlockField.tsx
    │       ├── ChoiceText.tsx
    │       └── InlineField.tsx
    ├── hooks/
    │   ├── useValidation.ts
    │   └── useWindowWidth.ts
    ├── store/
    │   └── projectStore.ts         # Zustand + localStorage
    ├── types/
    │   └── template.ts             # TypeScript-типы шаблона
    ├── utils/
    │   └── validation.ts
    ├── App.tsx
    └── main.tsx

### 4.1. App.tsx

Главный компонент. Содержит:

- шапку с кнопками «ИИ-помощник», «Скачать Word», «Сбросить проект»
  и тегом «Заполнено: X / 7»;
- левый сайдбар со списком разделов и иконками статуса;
- центральную область с содержимым выбранного раздела;
- правую панель ИИ (на широких экранах) или Drawer (на узких).

### 4.2. BlockRenderer.tsx

Ключевой компонент рендера. Получает JSON-блок и по его `type`
делегирует отрисовку нужному компоненту:

    block.type === 'heading'                 → <Title>
    block.type === 'paragraph'               → <ParagraphBlock>
    block.type === 'field_block'             → <BlockField>
    block.type === 'repeatable_group'        → <RepeatableGroup>
    block.type === 'formula_repeated_group'  → <FormulaBlock>
    block.type === 'classifier_paragraphs'   → <ClassifierParagraphs>
    block.type === 'optional_group'          → <OptionalGroup>

Это значит, что для добавления нового раздела достаточно положить JSON
в `backend/data/sections/` и добавить ссылку в манифест — фронтенд
подхватит его автоматически, без правки кода.

### 4.3. Состояние проекта

Хранится в Zustand-store `projectStore.ts`:

    {
      values: { [fieldName]: value },
      setValue, setAll, reset
    }

Каждое изменение автоматически сохраняется в localStorage по ключу
`methodology-project-v1`. При обновлении страницы значения
восстанавливаются. Кнопка «Сбросить проект» очищает хранилище.

### 4.4. Валидация

Файл `utils/validation.ts` содержит функцию `validateSection(section, values)`.
Она проходит по `validation.required_items` из JSON раздела и проверяет,
заполнены ли соответствующие поля.

Результат — объект:

    {
      status: 'empty' | 'in_progress' | 'problems' | 'complete',
      filled: number,
      total: number,
      missing: string[]
    }

На основе этого объект рисуются иконки у разделов в сайдбаре и
предупреждение перед скачиванием Word.

### 4.5. ИИ-помощник

Компонент `AiAssistant.tsx`:

- берёт текущий раздел из App;
- собирает контекст: заполненные строковые поля;
- отправляет запрос `POST /api/ai/assist`;
- отображает ответ с кнопкой «Скопировать».

Пользователь сам решает, применить ли предложение ИИ. Автоматически в
документ ничего не встраивается.

## 5. Поток данных

Последовательность при работе пользователя:

1. Frontend запрашивает `/api/template` и получает манифест.
2. Пользователь кликает раздел — запрашивается
   `/api/template/sections/{id}`.
3. `BlockRenderer` строит интерфейс по JSON-блокам.
4. Значения полей сохраняются в Zustand и localStorage.
5. При запросе ФПСР фронт ищет по уже загруженному справочнику.
6. Для ИИ собирается контекст и отправляется на `/api/ai/assist`.
7. При нажатии «Скачать Word» frontend отправляет `POST /api/export/docx`
   с текущими значениями.
8. Backend прогоняет значения через `word_builder` и возвращает DOCX.

## 6. Что можно расширить

Архитектура готова к доработкам:

- **Серверное хранение проектов** — добавить таблицу в SQLite и эндпоинты
  сохранения/загрузки; store на фронте заменить на подгрузку с сервера.
- **Несколько шаблонов методологии** — сейчас манифест один; можно
  добавить параметр `template_id` и выбирать его в UI.
- **Импорт существующих документов** — эндпоинт, принимающий DOCX,
  извлекающий текст и размечающий его по полям шаблона с помощью ИИ.
- **История версий** — хранить снапшоты состояния проекта.
- **Дополнительные справочники** — по аналогии с ФПСР.
